# P04 · Bank transaction coding

**Current version:** v1.2 · **Status:** Tested · **Workflow stage:** Bookkeeping 1 · **Feeds into:** P05

> Sample portfolio for BUS4005 Assessment 1. Harbourside Accounting and all figures are invented. Use the structure, not the content.

## Prompt text

```text
You are an assistant bookkeeper for small Australian businesses. Suggest an
account code for each transaction. Business type: [BUSINESS_TYPE].
Use ONLY codes from this chart of accounts: [CHART_OF_ACCOUNTS].
Client-specific rules: [CLIENT_RULES]. Transactions: [TRANSACTIONS_CSV].
Reply with a JSON list: {"date":"", "description":"", "amount":0,
"suggested_code":"", "confidence":"high|medium|low", "note":""}
If a transaction could be private or business, or matches no rule, set
confidence to "low" and explain why. Do not decide GST treatment.
```

## Workflow / task

Bookkeeping, step 1. Runs when the monthly bank feed is imported; the bookkeeper accepts high-confidence codes in bulk and codes the rest by hand.

## Problem solved

About 15,000 transactions a month across 120 clients, most of them repeats, are coded one by one, and different bookkeepers code them inconsistently.

## Automation potential

High, as suggestions only. In a 20-transaction test, all 10 high-confidence codes were correct; the other 10 needed a person.

## Risks & limitations

Wrong code changes a client’s figures → every code accepted by a bookkeeper, quarterly review by the accountant. Invented codes → grounding to the chart of accounts. Client bank data in an AI tool → only the firm’s licensed tool, no account numbers in the data.

## Version history

> Earlier versions are illustrative: they show how a version log should read, but only the current version was run in testing.

| Version | Change made | What happened | Lesson |
|---|---|---|---|
| v1.0 | “Code these transactions.” | Invented 3 account codes that do not exist | Ground it in the chart of accounts |
| v1.1 | Added “Use ONLY codes from [CHART_OF_ACCOUNTS]” | No invented codes; mixed private spending coded as business | Ambiguous items need a rule |
| v1.2 | Added confidence levels, private/business rule, “do not decide GST” | Real test: 20 of 20 as expected; 10 high-confidence, all correct | Low confidence is a feature, not a failure |

## Test evidence

**Real test** — Claude Opus 5.5, 22 November 2026, current version only. 20-row bank feed: 20 of 20 coded as expected, no code outside the chart, no GST decision. 10 high-confidence (all correct), 5 medium, 5 low — so about half the rows could be bulk-accepted.
