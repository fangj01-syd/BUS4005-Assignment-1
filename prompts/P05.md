# P05 · Reconciliation exception summary

**Current version:** v1.2 · **Status:** Tested · **Workflow stage:** Bookkeeping 2 · **Feeds into:** P10

> Sample portfolio for BUS4005 Assessment 1. Harbourside Accounting and all figures are invented. Use the structure, not the content.

## Prompt text

```text
You are a senior bookkeeper writing a note for the client's accountant.
Summarise the unreconciled items for [CLIENT_NAME] for [MONTH].
Data: [EXCEPTIONS_TABLE]. Bookkeeper's comments: [BOOKKEEPER_NOTES].
Use ONLY the data provided. Give: (1) the number of items and total value;
(2) a table grouped by likely cause — missing invoice, duplicate, timing
difference, unknown; (3) up to 3 questions for the accountant to ask the
client. Under 200 words. If a cause is unclear, use "unknown" — do not guess.
```

## Workflow / task

Bookkeeping, step 2. Runs after month-end reconciliation; the bookkeeper checks it and the accountant uses it in the monthly client call.

## Problem solved

Accountants scroll raw exception lists before client calls, or a bookkeeper writes a summary by hand (about 20 minutes per client). Duplicate payments get missed in long lists.

## Automation potential

Medium. Grouping by cause needs judgement, so a bookkeeper checks every summary. About 20 → 5 minutes per client per month.

## Risks & limitations

Total miscalculated → bookkeeper checks it against the software. Wrong cause leads to the wrong client question → “unknown” instead of guessing.

## Version history

| Version | Change made | What happened | Lesson |
|---|---|---|---|
| v1.0 | “Summarise the unreconciled items.” | Guessed causes for 4 items with no evidence | Allow “unknown” |
| v1.1 | Added “use ONLY the data” and the “unknown” cause | Totals correct in 5 of 5 | Grounding fixes figures |
| v1.2 | Fixed structure: count, table by cause, 3 questions, 200 words | One duplicate grouped as timing; caught by bookkeeper | Some judgement stays human |

## Test evidence

5 sample exception lists: totals matched in 5 of 5. One duplicate was grouped as a timing difference; the bookkeeper check caught it.
