# P03 · Document intake classifier

**Current version:** v1.3 · **Status:** Tested · **Workflow stage:** Onboarding 3 · **Feeds into:** P02 (tracker), P10

> Sample portfolio for BUS4005 Assessment 1. Harbourside Accounting and all figures are invented. Use the structure, not the content.

## Prompt text

```text
You are a document intake assistant at an Australian accounting practice.
Classify the uploaded document. File name: [FILE_NAME]. First-page text:
[EXTRACTED_TEXT].
Use exactly one category: PAYG_SUMMARY, BANK_INTEREST, DIVIDEND_STATEMENT,
RENTAL_STATEMENT, WORK_EXPENSE_RECEIPT, PRIVATE_HEALTH, OTHER_NEEDS_REVIEW.
Reply with JSON only: {"category":"", "financial_year":"", "issuer":"",
"confidence":"high|medium|low"}
If the year or issuer is not stated, write "NOT FOUND". If unsure of the
category, use OTHER_NEEDS_REVIEW with confidence "low". Do not copy any TFN,
account number or address.
```

## Workflow / task

Onboarding, step 3. Runs on every upload; the result files the document and updates the tracker. Low-confidence items go to a person.

## Problem solved

Clients upload files like “scan_0034.pdf”. Staff open each one (about 1–2 minutes) across roughly 8,000 uploads a season, and misfiled documents get missed in returns.

## Automation potential

High. JSON can update the tracker directly; in testing 2 of 10 files went to the review queue.

## Risks & limitations

Misclassification → review queue for low confidence. Invented year or issuer → “NOT FOUND” rule. Personal identifiers spreading into other systems → excluded from output.

## Version history

> Earlier versions are illustrative: they show how a version log should read, but only the current version was run in testing.

| Version | Change made | What happened | Lesson |
|---|---|---|---|
| v1.0 | “What type of tax document is this?” | Free-text answers; categories changed between runs | Needs a fixed category list |
| v1.1 | Added fixed categories | Consistent, but a sentence the tracker can’t read | Needs a data format |
| v1.2 | Added JSON output | Guessed a financial year on 2 documents with no year shown | Tell the AI what to do when information is missing |
| v1.3 | Added “NOT FOUND”, confidence levels, identifier exclusion | Real test: 10 of 10 correct; 2 unclear files sent to review | Uncertainty rules make output reliable |

## Test evidence

**Real test** — Claude Opus 5.5, 22 November 2026, current version only. 10 of 10 categories correct; valid JSON every time; no TFN or address copied; unclear files sent to review. Finding: where a document showed a date but no financial year, it worked out the year itself instead of writing NOT FOUND. Full inputs and outputs: [tests/P03.md](../tests/P03.md).
